# Tadado Skill — AI 任务管理通道

Tadado 是本地 Windows 任务管理软件。本 skill 通过其 CLI（`tadado-cli.exe`）实现任务
的增删改查，与用户在 GUI 里的操作完全等价、共享同一份数据。

## 定位执行程序（按顺序尝试）

1. 环境变量 `TADADO_EXE` 指向的可执行文件（若设置，直接使用）
2. 打包版 `tadado-cli.exe`，候选位置：
   - `C:\Program Files\Tadado\tadado-cli.exe`
   - `C:\Program Files (x86)\Tadado\tadado-cli.exe`
   - 便携版所在目录下的 `tadado-cli.exe`（用户提供路径时）
3. 开发回退（在 Tadado 仓库根目录执行）：`uv run python main.py --cli ...`

统一用法：`<执行程序> <命令> [参数]`。默认输出 JSON（`--format human` 给终端用户看）。

## 运行行为（重要）

- 若 Tadado GUI 正在运行：命令自动通过本地管道转发给 GUI 执行，界面实时刷新。
- 若报「版本过旧」：GUI 是旧版，请用户关闭 GUI 或升级到 0.2.7+。
- 若 GUI 未运行：CLI 以 headless 模式独立执行（同进程内复用 TaskService 逻辑）。
- `TADADO_DATA_DIR` 可覆盖数据目录；`TADADO_NO_FORWARD=1` 禁用转发（脚本/CI 用）。

## 命令速查

| 命令 | 用途 | 关键参数 |
|------|------|----------|
| `list` | 查询任务 | `--status TODO/DOING/DONE/OVERDUE`（可多次）`--tag` `--keyword` `--from/--to`（截止日范围）`--overdue` `--archived` `--urgency 0-3` `--limit` `--offset` `--sort deadline/urgency/created/title/status/scheduled` `--desc` |
| `today` | 今日摘要 | `--days N`（临近窗口，默认 2）`--partition` |
| `activity` | 活动记录时间线 | `--date YYYY-MM-DD`（默认今天）`--partition` `--tag` |
| `add` | 新建任务 | 位置参数=Markdown 行，或 `--title` + `--due "YYYY-MM-DD[ HH:MM]"` `--scheduled` `--tags "a,b"` `--urgency 0-3` `--status` `--notes` `--recur +1d/+1w/+1m/+1y` `--partition` |
| `edit` | 修改任务 | `<id>` 或 `--match 关键词` + 同 add 的字段参数 + `--clear-due` `--clear-scheduled` `--partition`（移动）`--dry-run` |
| `done` | 状态变更 | `<id>` 或 `--match`，`--status`（默认 DONE，可 DOING/TODO 回退），`--dry-run` |
| `log` | 追加活动进展 | `<id>` 或 `--match` + `--content 内容`，可选 `--status` `--progress 0-100`（选 DONE 同时完成任务），`--dry-run` |
| `rm` | 删除任务 | `<id>` 或 `--match`，`--dry-run` |
| `tags` | 标签列表 | `--partition`，`--counts`（含计数） |
| `partitions` | 分区管理 | `--add NAME` / `--rename ID NAME` / `--rm ID`，无参=列表 |
| `archive` | 归档 | `<ids>` / `--match` / `--all`（全部已完成），`--dry-run` |
| `recurrence` | 周期规则 | `<id>` 或 `--match`，`--rule +1d/+1w/+1m/+1y`；无 `--rule`=查看 |
| `reminder` | 提醒配置 | `--enable` `--disable` `--digest-time HH:MM` `--quiet-start/--quiet-end HH:MM` |
| `export` | 导出 | `--fmt md/xlsx` `--partition` `--out PATH` |
| `report` | 周报/月报摘要（直读库，区别于活动分析导出） | `--period week/month`（默认 week）`--offset -1`（上一周期）`--from/--to` `--partition` `--tag` |

### Markdown 任务行语法（与 GUI 相同）

```
- [*] TODO <2026-08-20> 买咖啡 #工作
```

- `[ ]` 内 `*` 数量表示优先级：`***`=紧急(0) `**`=重要(1) `*`=关注(2) 空=普通(3)
- 状态关键字可选：`TODO / DOING / DONE / OVERDUE`（注意与 `<日期>` 之间要有空格）
- `<日期[ 时间]>` 最多两个：第一个=计划日，第二个=截止日；**只写一个时**：
  无状态关键字→截止日；有状态关键字（如 `DONE <日期>`）→计划日。
  要设截止日务必用 `--due` 或双日期，创建后可在回执校验 `deadline_date`。
- `#标签` 结尾

## 输出 JSON 要点

任务对象字段：`id`、`title`、`raw_md`、`status`（`TODO/DOING/DONE/OVERDUE`）、
`status_display`（中文）、`tags`、`urgency`（0-3）、`progress`、`archived`、
`suspended`、`scheduled_date`、`deadline_date`、`deadline_time`、`partition_id`、
`partition_name`、`recurrence_rule`、`notes`、`is_overdue`、`completed_at` 等。
`list` 返回 `{type, count, total, tasks}`；`today` 返回
`{type, date, days, overdue, due_today, due_soon, doing}` 四组任务。

## 会话上下文与消歧（降低输入负担的核心）

用户不需要精确说明分区/标签/任务——由本 skill 维护上下文并自动消歧：

- **当前分区（像终端的工作目录）**：记住用户最后一次明确指定的分区。此后所有命令
  默认作用于此分区，回执中始终标注分区。用户说「切到工作分区」→ 仅更新上下文；
  说「工作分区里的任务」→ 同时切换并执行。
  **双层保险**：① 每个分区作用域命令（list/today/tags/report/export/activity/add）
  **必须显式传 `--partition <当前分区>`**，绝不依赖默认值；② 托盘启动的会话会注入
  `TADADO_PARTITION` 环境变量，CLI 在未显式指定时自动默认到该分区——即使漏传
  也不会查错分区。回执中发现分区与上下文不符时立即纠正。
- **最近任务指代**：每次操作后记住任务 ID 与标题。用户说「刚才那个」「刚建的那个」
  → 直接对最近操作的任务执行；「把买咖啡那个标成已完成」→ `--match 买咖啡`。
- **裸词消歧顺序**（用户只给一个词，如「工作」）：
  ① 分区名精确匹配 → 视为分区；② 标签匹配（如存在 #工作）→ 视为标签过滤；
  ③ 任务关键词 → `--match`。当 ①② 同时存在时**只反问一句**：
  「是指『工作』分区，还是带 #工作 标签的任务？」，不要自己猜。
- **带标记词直接判定**：「#x」→ 标签；「x分区」→ 分区名；「x任务/x那个」→ 关键词。
- **拿不准就问，不猜**：日期残缺（「计划天完成」）、分区名重名等，反问一句确认；
  能确定的字段直接执行，在回执中注明推断依据（如「按『一周』推断截止 2026-08-21」）。
- **typo 容忍**：明显错别字/漏字结合上下文修正，并在回执中注明修正内容。

### 自然语言字段映射

- **截止时间严格按系统「快捷计算」六预设推断**（不得自行计算其他日期）：
  | 用户表述 | 预设 | 结果 |
  |----------|------|------|
  | 今天/当日 | 今天 | 当日 23:59:59 |
  | 明天 | 明天 (+1天) | +1 天 |
  | 本周/周日 | 本周日 | 本周日（`7 - isoweekday`） |
  | 一周后/下周 | 一周后 (+7天) | +7 天 |
  | 本月末/月底 | 本月末 | 本月最后一天 |
  | 下月今天/一个月后 | 下月今天 (+1个月) | +1 月（月末溢出取该月最后一天） |
  其余表述（如「三天后」「下周五」）不属于预设 → **反问用户选择六预设之一**。
- **优先级词**：紧急/urgent→0，重要→1，关注→2，普通/无提及→3。
- **分区定位**：`--partition` 支持分区名称、≥8 位 ID 前缀、完整 ID。

## 安全规则（必须遵守）

- **破坏性操作先确认**：`rm`、`archive` 必须先用 `--dry-run` 拿到将操作的任务列表，
  展示给用户并得到确认后才能执行真实命令。`edit` 建议同样先 `--dry-run` 展示修改前后。
- **免确认操作**：`list` / `today` / `tags` / `partitions` / `activity`（查看）、`add`、
  `done`、`log`、`recurrence`、`reminder`（低风险）。
- `--match` 关键词命中多个任务时会报错并列出候选，此时改用任务 ID 指定。
- 操作结果向用户汇报时使用 `status_display` 等中文显示字段。

## 内置工作流

1. **今日摘要**：运行 `today` → 按「逾期 / 今日到期 / 临近 / 进行中」分组，
   用中文简报呈现（含截止日和优先级），逾期项优先提醒。
2. **快速添加**：用户自然语言描述 → 转换 Markdown 行（继承当前分区；截止时间按
   「快捷计算」六预设推断；优先级按词映射）→ 预览确认 → `add` → 回执。
   **标签必问**：用户未提供标签时，必须向用户确认标签后再写入（与 GUI 的
   「标签缺失」校验一致），不得替用户编造标签。
3. **批量添加**：用户一次给出多条任务 → 逐条解析 → **展示完整预览表格**
   （标题/截止/分区/标签/优先级）→ 请用户确认；用户提出修正 → 修正后**重新预览**，
   循环直至用户确认无误 → 才逐条 `add` → 汇总回执。
   **写入前提 = 多次确认无误**：任何字段（尤其标签、截止时间）未经确认不得写入。
   预览中缺标签的任务必须标注「⚠️ 待确认标签」，在确认环节一并收集。
4. **周报摘要**（默认上一周）：`report --period week --from 上周一 --to 上周日`
   **必须带 `--partition <当前分区>`**（与活动分析按单一分区触发一致，缺省时用默认分区）。
   输出：「本周工作内容」+「下周工作计划」，按任务标签 `#xx` 分组、编号列表——
   **默认导出全部活动标签**，仅当用户明确指定某标签时才用 `--tag` 过滤。
   条目格式 `N. 标题：要点1；要点2；`（要点=期内活动日志，剔除 批量操作/
   状态变更 噪声）；无要点条目只写标题。**每个任务归入其每一个标签组**
   （多标签任务在多个 #组 下出现，标签属性不丢失）；组内有进展条目在前，
   「（无进展）」条目聚合在后。
   「本周工作内容」= 期内完成 / 期内有实质进展 / **期内创建**（创建本身即本周工作）；
   仅创建、未补进展的任务在条目后标注**「（无进展）」**，提示用户自行补充修改。
   「下周计划」= 期前遗留 + 期内创建无进展的未完成任务，其中**期内创建的优先排列**，
   逾期项标注 ⚠️。输出可直接粘贴进汇报。
5. **月报摘要**：同周报，`--period month`，默认本月，分区与标签语义一致。

### 回执规范（与系统保持一致）

- **统一行格式**（列表与单条回执共用）：
  `[ID前8位] 状态 截止日期 (倒计数) 标题 #标签 「分区」`
- **倒计数规则**：截止日 - 今天 = N → 未来「剩 N 天」；当天「今天到期」；
  已过「已逾期 N 天」；无截止不显示倒计数。
- 日期一律完整 `YYYY-MM-DD`（不得缩写「月/日」）；带时间时显示 `HH:MM`。
- 状态用系统中文：待办/进行中/已完成/逾期；优先级用：紧急/重要/关注/普通。
- 回执字段与 GUI 一致：标题、状态、截止、分区、标签、优先级。
3. **周回顾**：`list --status DONE --from <本周一>` 统计本周完成 +
   `today` 看遗留/逾期 → 生成简报：完成数、进行中、逾期项与重排期建议。

## 注意事项

- **实例身份校验**：转发请求携带 app 版本与数据目录，GUI 校验不一致会拒绝执行
  （「版本不一致」/「数据目录不一致」）——保证 CLI 写入的始终是同一版本、同一数据目录的实例。
- **ID 前缀**：任务/分区的 ID 可用 ≥8 位的唯一前缀代替完整 UUID
  （如 `done 1ee735cf`）；前缀不唯一或过短会报错。
- 分区密码是 UI 层保护，CLI 不受限（本机信任边界）。
- 周期任务完成（`done`）时若带 `--recur` 规则，Tadado 自动生成下一期任务。
- 分区默认 `archive_days=0` 时，任务完成即自动归档（`list` 默认不含已归档任务，
  需加 `--archived`）。
